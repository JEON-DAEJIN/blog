블로그 자동배포 구축법

글 파일 추가 + git push, 그것으로 끝나는 배포

정적 사이트 생성기(Jekyll)로 블로그를 만들고 GitHub Actions에 배포를 맡기면, 그 다음부터는 글 파일을 추가하고 git push만 하는 것으로 배포가 끝납니다.

1. 이 매뉴얼로 할 수 있는 일

Git·GitHub을 막 배운 단계에서도, 블로그 하나를 완전히 자동 배포되는 형태로 갖출 수 있습니다. 한 번 구축해두면 그 다음부터 해야 할 일은 딱 하나 — 글 파일을 추가하고 git push 뿐입니다.

2. 전체 그림 — 세 조각의 관계

조각역할
Jekyll (+ Chirpy 테마)마크다운 글을 읽어 실제 웹페이지(HTML)로 변환하는 정적 사이트 생성기
GitHub 저장소마크다운 원고와 설정 파일이 저장되는 곳
GitHub Actionsmain 브랜치에 push가 일어날 때마다 자동으로 Jekyll을 실행해 사이트를 빌드하고 GitHub Pages에 올려주는 자동화 로봇
💡 팁 이 구조를 한 번 갖춰두면, "배포"라는 행위 자체를 신경 쓸 필요가 없어집니다. 신경 써야 할 건 오직 "글을 쓰고 push했는가"뿐입니다.

3. 1단계 — 로컬 환경 확인

시작하기 전에 확인할 것은 딱 하나, git이 설치돼 있는가입니다. (gh CLI는 있으면 편하지만 필수는 아닙니다.)

🧪 예제 "AI 학습 과정에 대한 일지를 써보고 싶다"는 목표 하나와, 미리 만들어 둔 빈 GitHub 저장소 링크 하나만 있어도 시작할 수 있습니다. 테마도, 배포 방식도, 로컬에 뭐가 깔려 있는지도 정해지지 않은 백지 상태에서 시작해도 됩니다 — 그것부터 하나씩 확인하면 됩니다.

4. 2단계 — 테마 가져오기

Jekyll 테마 중 인기 있는 것(예: Chirpy) 스타터 템플릿을 내 저장소 위치로 가져옵니다.

⚠️ 주의 — 스타터의 .git 폴더까지 덮어쓰지 않기 테마 스타터를 통째로 복사할 때, 그 폴더 안에 있는 .git 폴더(스타터 자체의 Git 이력)까지 같이 복사해버리면 내 저장소의 원격 정보가 스타터 쪽으로 꼬여버립니다. 복사 후에는 반드시 .git 폴더가 내 저장소의 것인지 확인하세요. (실수로 덮어썼다면 원격 주소를 다시 내 저장소로 설정하면 되돌릴 수 있습니다.)

5. 3단계 — 기본 정보 채우기

  • _config.yml에서 블로그 제목, 설명, 소셜 링크 등 기본 정보를 내 것으로 바꿉니다.
  • 소개 페이지(예: _tabs/about.md)를 채웁니다.
  • 첫 글 하나를 씁니다.
💡 팁 완벽하게 채우고 시작할 필요 없습니다. 첫 글은 "시작하며" 같은 짧은 인사말이어도 충분합니다 — 일단 배포 파이프라인이 도는지 확인하는 게 먼저입니다.

6. 4단계 — 커밋·푸시와 인증

여기서부터는 일반적인 Git 작업(git add, git commit, git push)입니다. 다만 Git·GitHub을 처음 쓰는 경우, git push 시점에 브라우저 인증 창이 뜰 수 있습니다.

🧪 예제 git push를 실행했는데 터미널이 응답 없이 멈춰 있고, 화면에 "Sign in with your browser"라는 옵션이 보이는 경우가 있습니다. 이건 GitHub이 신원을 확인하려는 것이니, 그 옵션을 선택해 브라우저에서 로그인하면 됩니다. 인증이 끝나면 멈춰 있던 터미널이 이어서 push를 완료합니다.

7. 5단계 — GitHub Pages를 Actions 배포로 전환

GitHub 저장소 설정 화면에서 Settings → Pages → Build and deployment → Source를 "Deploy from a branch"가 아니라 "GitHub Actions"로 바꿉니다.

⚠️ 주의 — 이 단계는 코드로 대신할 수 없다 여기까지는 전부 터미널·코드로 처리할 수 있었지만, 이 설정만큼은 GitHub 웹 화면에서 직접 클릭해야 하는 GUI 작업입니다. 그리고 이 화면에는 별도의 "저장" 버튼이 없습니다 — 드롭다운에서 옵션을 선택하는 것 자체가 저장입니다. 개발자에게는 당연한 관례지만, 처음 보면 "저장은 어떻게 하지?"라는 의문이 들 수 있는 지점입니다.

8. 6단계 — 첫 배포 확인

배포된 주소로 접속했을 때 404가 뜨는 경우가 흔합니다. 당황하지 말고 원인을 직접 확인하세요.

🧪 예제 push 직후 첫 자동 빌드가 "Pages가 아직 활성화되지 않음" 오류로 이미 실패해 있는 경우가 있습니다. Pages 설정을 나중에 켰다고 해서 이미 실패한 실행이 저절로 재시도되지는 않습니다. 저장소의 Actions 탭에서 실패한 워크플로우를 찾아 "Re-run all jobs"(안 보이면 "Run workflow")로 다시 실행하면 됩니다.
💡 팁 화면이 안내받은 것과 다르게 생겼다면(메뉴 이름이 다르거나 버튼이 안 보이면), 같은 목적을 달성하는 다른 버튼이 근처에 있을 가능성이 높습니다. GitHub UI는 계속 바뀌므로, 정확한 버튼 이름보다 "무엇을 하려는 것인지"에 집중하세요.

9. 이후 — 새 글 쓰는 법

한 번 이 구조가 갖춰지면, 새 글을 올리는 절차는 늘 같습니다.

1. _posts/YYYY-MM-DD-제목.md 파일을 새로 만든다
2. 글을 쓴다
3. git add, git commit, git push

이게 전부입니다. push 순간 Actions가 자동으로 빌드·배포합니다.

10. 실전 예시로 뜯어보기

🧪 예제 실제로 JEON-DAEJIN/blog 저장소에서 이 과정을 그대로 밟았습니다. Chirpy 테마를 가져오다 .git 폴더가 꼬이는 사고가 있었지만 되돌렸고, _config.yml·소개 페이지·첫 글("AI 학습 일지를 시작하며")을 채운 뒤 push했습니다. 인증 창에서 "Sign in with your browser"를 선택해 풀었고, Pages Source를 Actions로 바꾼 뒤 404를 만나 Actions 로그에서 원인(Pages 미활성 상태에서 실패한 첫 워크플로우)을 확인해 재실행으로 해결했습니다. 이후로는 _posts/에 파일을 추가하고 push만 하면 자동 배포되는 구조가 완성됐습니다.

📎 부록 A · 체크리스트

  • ☐ git이 로컬에 설치돼 있는지 확인했다
  • ☐ 테마 스타터를 복사할 때 .git 폴더가 내 저장소 것인지 확인했다
  • ☐ _config.yml·소개 페이지·첫 글을 채웠다
  • ☐ push 시 인증 창이 뜨면 브라우저 로그인으로 처리했다
  • ☐ Pages Source를 "GitHub Actions"로 바꿨다 (드롭다운 선택 자체가 저장임을 인지)
  • ☐ 첫 배포 후 실제 사이트에 접속해 제목·글·내비게이션이 정상인지 확인했다

📎 부록 B · 트러블슈팅

증상원인해결
테마 복사 후 원격 저장소 정보가 이상해짐스타터의 .git 폴더까지 함께 복사됨원격 주소를 내 저장소로 다시 설정, 또는 .git 폴더 삭제 후 내 저장소로 재초기화
git push가 멈추고 응답 없음브라우저 인증 대기 중화면의 "Sign in with your browser" 선택 후 브라우저에서 로그인
Pages 설정 화면에 저장 버튼이 안 보임드롭다운 선택 자체가 저장이라 별도 버튼이 없음옵션을 선택하는 것으로 완료된 것이니 추가 조작 불필요
배포 주소 접속 시 404첫 워크플로우가 Pages 미활성 상태에서 이미 실패Actions 탭에서 "Re-run all jobs" 또는 "Run workflow"로 재실행
안내받은 메뉴 이름·버튼이 화면에 안 보임GitHub UI 변경 또는 화면 구성 차이같은 목적의 다른 버튼을 근처에서 찾아 시도
